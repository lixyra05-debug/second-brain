# Les 5 niveaux d'un second brain avec Claude

## Source
« Every Level of a Claude Second Brain Explained » — Nate Herk (YouTube, 30 min) : https://www.youtube.com/watch?v=DTCyvo6cC54

## Résumé (5 lignes max)
Cinq niveaux de second brain sur Claude Code, classés par la question qu'ils savent traiter : mot exact (CLAUDE.md routeur), tout un sujet (wiki LLM), recherche par sens (base vectorielle), chaînes de relations (knowledge graph), système autonome always-on. Règle centrale : rester au niveau le plus bas qui résout une douleur réelle — Nate reste lui-même au niveau 2. Tout n'est que markdown + dossiers, donc agnostique de l'outil, et un même vault peut mélanger les niveaux dossier par dossier.

## Points clés
- Raisonner à l'envers : la façon dont on interrogera la donnée détermine comment la stocker (le ballon est conçu pour le panier).
- Test permanent : « mon agent peut-il le retrouver ? » Sinon c'est un problème de routage, pas d'IA.
- N1 — routeur : CLAUDE.md avec règles explicites (« pour X, regarde le dossier Y ») + context/, decisions/, projects/.
- N2 — wiki : pages d'index et backlinks créés à l'ingestion ; Obsidian n'est qu'une couche de visualisation ; memory.md auto-entretenu par Claude Code.
- N3 — vectoriel : fort sur les gros volumes et les questions ponctuelles précises ; faible sur le contexte global (résumer une réunion entière) → garder des fichiers entiers pour ça.
- N4 — knowledge graph : relations typées (« travaille chez », « concurrent de ») ; le goulot est l'alimentation → skill « Grill Me » qui t'interviewe pour extraire ce que tu as en tête.
- N5 — always-on (Gbrain) : ingestion autonome en continu ; risque du trop-plein de contexte, Nate préfère garder l'ingestion sous contrôle.
- Filtre evergreen : dans le vault, seulement ce qui servira encore dans un an ; le volatil (Slack, mails, tickets) reste dans l'outil source — le vault sait juste où chercher, et dans quel ordre.
